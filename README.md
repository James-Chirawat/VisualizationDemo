# RouteLens — Visualization Demo

แดชบอร์ดติดตามการขนส่งและวิเคราะห์ KPI ใช้ Next.js App Router, TypeScript, Tailwind CSS, คอมโพเนนต์แบบ shadcn/ui (Radix), Recharts และ Lucide React

## เริ่มใช้งาน

ใช้ Node.js 22 ขึ้นไป

```sh
npm ci
npm run dev
```

เปิด http://localhost:3000
ตรวจ TypeScript ด้วย `npm run typecheck` หรือสร้าง production build ด้วย `npm run build` แล้วเปิดด้วย `npm start`

## แชตและ LINE OA ในโหมดสาธิต

AI Analyst คำนวณคำตอบจากข้อมูลจำลองและตัวกรองในหน้าเว็บผ่าน `/api/chat` โดยไม่ต้องตั้ง environment variable หรือ API key ปุ่มแนบไฟล์รองรับ CSV, TSV และ TXT สูงสุด 2 MB และสรุปโครงสร้างไฟล์ในเบราว์เซอร์

หน้า LINE OA แสดงสถานะเชื่อมต่อจำลองและตัวอย่าง Flex Message แบบต้นทาง–ปลายทางและไทม์ไลน์เที่ยวขนส่ง จากเส้นทางที่อัตราตรงเวลาต่ำกว่า 80% กฎใช้ช่วงวันที่และเส้นทางที่เลือก และนับทุกสถานะเพื่อคงฐานคำนวณ ปุ่มจำลองส่งเปลี่ยนสถานะบนหน้าเว็บเท่านั้น โลโก้จาก [LINE Brand Icon](https://www.line.me/en/logo)

## ลำดับสาธิต

1. เริ่มทุกเส้นทาง เห็น 150 เที่ยว ส่งตรงเวลา 114 จาก 144 เที่ยวที่ส่งถึงแล้ว (79.2%) ค่าใช้จ่ายรวม 590,751 บาท
2. คลิกแท่งหรือปุ่ม **R-02** หน้าจอเปลี่ยนเป็น 21 เที่ยว โดยส่งถึงแล้ว 20 เที่ยว ตรงเวลา 11 เที่ยว (55%) และล่าช้า 9 เที่ยว
3. ดูสาเหตุที่บันทึกและตัวอย่างคนขับ เปิดเที่ยวที่ส่งช้าจากตารางเพื่อเทียบวันกำหนดกับวันส่งถึงจริง
4. เปิด **AI Analyst** แล้วถาม “ทำไมส่งล่าช้า และควรตรวจอะไรต่อ?” คำตอบสาธิตอ้างฐานคำนวณและสาเหตุที่บันทึกไว้ตามตัวกรอง
5. เปิด **LINE OA** แล้วลองจำลองส่ง Flex Message สำหรับ R-02
6. เปลี่ยนช่วงวันที่หรือสถานะ ตรวจว่ากราฟ ฐานคำนวณ และรายการเปลี่ยนตาม แล้วกดส่งออก CSV สำหรับช่วงที่เลือก

ข้อมูล 150 แถวเป็นข้อมูลจำลองคงที่ สร้างเพื่อให้สาธิตการกรองและดูรายละเอียดได้ในตัว เลข KPI หลักและ R-02 อ้างกรณีจากสไลด์ ส่วนตัวเลขรายเส้นทางและรายการอื่นคำนวณจากข้อมูลจำลองในเว็บตามจริง ตัวกรองวันที่ใช้วันที่สั่ง อัตราตรงเวลานับเฉพาะเที่ยวที่ส่งถึง ค่าใช้จ่ายเฉลี่ยนับทุกเที่ยวในตัวกรอง และวันล่าช้าเฉลี่ยนับเฉพาะเที่ยวที่ล่าช้า
